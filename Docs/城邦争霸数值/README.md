### 字段含义（按 `§_-cv§` 构造参数顺序还原）

| 字段 | 含义 | 说明 |
|---|---|---|

## 2. 建筑

| 建筑 | 基础HP | 金币/秒 | 法力/秒 | 补给点 | 终极充能/秒 | 可造兵种 |
|---|---|---|---|---|---|---|
| 城镇 TOWN | 500 | 2 | 0 | 1 | 0 | 步兵 / 弓兵 |
| 要塞 CASTLE | 1000 | 3 | 1 | 2 | 0 | 步兵 / 弓兵 / 骑兵 / 攻城 |
| 营地 CAMP | 500 | 1 | 0 | 0 | 0 | 步兵 / 弓兵 |
| 魔法塔 MAGIC TOWER | 500 | 1+修正 | 2+修正 | 1+修正 | 1 | 步兵 / 特殊 |

- **升级**：最高 2 级（可升 2 次）。0→1 级 **350 金**，1→2 级 **500 金**。
- **升级 HP**：`HP = 基础HP × (1 + 0.5 × 等级)`，即 1 级 ×1.5、2 级 ×2.0。
- **附属槽位**：每座大建筑 3 个（城镇/要塞/营地/魔法塔一致）。
- 城镇/要塞的 `+修正` 来自教令（见第 6 节），例如“-30% 矿场与英雄碑造价”。

## 4. 经济公式

| 项目 | 数值 / 公式 | 代码位置 |
|---|---|---|
| 法力初始 / 上限 | 0 / **500** | `§_-J1§.§_-Qv§` |
| 基础金币收入 | 所有己方建筑「金币/秒」之和 | `§_-r5§` 聚合 → `§_-rJ§` |
| **金币净收入** | `round(基础收入 × (100 − (25 + 5 × min(部队数, 10))) / 100)`，最低 1 | `§_-J1§.§_-34§` |
| 部队数惩罚 | 1 队 −30%、2 队 −35% …… 10 队及以上 −75% | `§_-J1§.§_-1q§` |
| 法力收入 | 所有己方建筑「法力/秒」之和 | `§_-rJ§` |
| 补给上限 | 所有己方建筑「补给点」之和 | `§_-rJ§` |
| 补给占用 | 所有存活部队 `upkeep` 之和 | `§_-r5§.§_-gW§` |
| 终极技能充能上限 | `200 × (100 + 修正值)/100` | `§_-J1§.§_-Dy§` |
| 终极充能来源 | 魔法塔 +1/秒，或击杀/死亡等事件 | `§_-RH§` |
| 金币宝箱 | **500 金**（固定，食人魔守护） | `level.§_-UD§.collect` |

> 注意“部队数”用的是**小队数**（squad count），不是补给占用；所以 3 队弓兵和 3 队投石机的收入惩罚相同。
> 收入惩罚项 `25 + 5n` 在 n≥10 时封顶 75%，与 `§_-1q§` 的 `25 + 5n`（n<10，否则 75）是同一公式。

## 6. 教令/修正器

修正器是一张 45 槽的表（id 0-44），每个槽存一个百分比，`§_-qn§(id)` 返回 `(100 + v)/100` 的乘数。
游戏里能看到的效果文本（从字符串池提取，对应 id 未全部锁定）：

- 法术消耗 −20% / −10%
- 终极技能冷却 −30% / −10%
- 矿场与英雄碑造价 −30% / −15%
- 亡灵部队造价 −15% / −7%
- 对要塞伤害 +50%
- 攻城器械移速 +50%
- 小队阵亡时终极充能 +6%
- 冰冻几率 +7%
- 建筑 HP +50%（升级到 2 级时额外效果）
- 招募费 −X%、收入 +X% 等

> 完整 id → 名称映射在 `progress.Badges` 与 `gui.BadgesRoomScreen`，未逐条对齐；

## 8. 自己复现的方法

```powershell

Invoke-WebRequest -Uri "http://sxiao.4399.com/4399swf/upload_swf/ftp8/chenweihong/20120920/takeover104.swf" -Headers $h -OutFile takeover104.swf

# 2. 反编译（需要 Java；Unity 自带的 OpenJDK 就够）
& "$env:ProgramFiles\Unity\Hub\Editor\2022.3.20f1-x86_64\Editor\Data\PlaybackEngines\AndroidPlayer\OpenJDK\bin\java.exe" `
  -Xmx4g -jar ffdec\ffdec.jar -onerror ignore -export script out_script takeover104.swf
```

- `out_script\scripts\§_-2J§\§ for§.as` — 16 个法术

## 9. 数值设计观察（可直接用于复刻）

1. **单位价格只有 5 档**（100/120/150/180/200），靠同一价格下的 HP 与伤害拉开强度，所以“同价换阶”是核心节奏。
2. **弓兵攻击间隔 3s、步兵 1.5s、投石机 5s**，DPS 差距被编制人数（9/9/1）抵消，投石机靠 200 射程与 50% 对建筑加成定位。
3. **收入随部队数线性下滑到 −75%**，逼玩家在“暴兵”和“攒钱升级”之间取舍；这是本作最有辨识度的一条曲线。
4. **升级费用 350/500 相当于 3.5-5 个步兵**，而 2 级建筑 HP ×2.0、解锁 3 阶兵，性价比明显偏向“先升级再爆兵”。
5. **补给点极稀缺**（城镇 1、要塞 2、农场 +1），所以农场 150 金买 1 补给 ≈ 买 1.5 个步兵的价钱换 1 个兵位，前期必须先铺农场。

## 10. 地图布局

### 地图是怎么定义的

游戏**没有任何外部地图文件**。每张地图是一个 Flash 影片剪辑 `Level{NN}GraphMarkersClass`，里面按实例名摆放标记，坐标就是标记在舞台上的位置（twips / 20 = 像素），运行时 `LevelParser.§_-6Z§()` 遍历子对象：

| 实例名规则 | 含义 |
|---|---|
| `l{区段}nd_{节点ID}` | 图节点。区段 00-07 只是美术分层，节点 ID 才是键 |
| `ed_{节点A}_{节点B}` | 一条道路，连接两个节点 ID |

节点的“建筑类型 + 归属阵营”由**标记的符号类名**决定，而不是数据字段：

| 符号类 | 建筑 | 归属 |
|---|---|---|
| `NodeCastleGreen/TownGreen/...` | 要塞/城镇/营地/魔法塔 | 绿 = 西利亚公国 |
| `NodeCastleRed/...` | 同上 | 红 = 卡若米森部落 |
| `NodeCastleBlue/...` | 同上 | 蓝 = 艾斯得雷邪教 |
| `NodeCastlePurple/...` | 同上 | 紫 = 瑞维迪斯帝国 |
| `NodeBuildHere` | 可建造空地 | 中立 |
| `NodeChest` | 宝箱（固定 500 金） | 中立 |
| `NodeDefenderOgre` | 食人魔守卫（守护宝箱） | 中立 |
| `EmptyNode` | 纯路径节点（无建筑） | 中立 |

> **玩家阵营按章节变化**：第 1 章（L1-8）玩家是西利亚（绿），第 2 章（L11-18）是卡若米森（红），第 3 章（L21-28）是艾斯得雷（蓝）；瑞维迪斯（紫）始终是敌方。所以“绿=玩家”只对第一章成立。

坐标在游戏里会做等距压缩：`y × LevelVisual.Y_KOEFF`（Y_KOEFF = 2），CSV 里存的是原始舞台坐标。

## 12. 地图相关的其他结论

- 每关**可建造点数量**在 2-18 个之间波动（L1 只有 2 个，L99 有 18 个），是关卡难度的主要调节手段。
- 宝箱与食人魔**永远成对出现**（数量完全相等），每个宝箱都有一个食人魔守着。
- 玩家（绿）在每关至少有一个要塞作为出生点；`L1` 是 1 个绿要塞 + 2 个紫要塞的最小教学局。
- 道路是**无向图**，没有单行道；`L1` 的 7 条路构成一个环 + 两条支路。

## 13. 战斗结算（复刻必需）

伤害不是“攻击力减护甲”，而是**小队总伤害的一次随机 + 倍率结算**：

```
每次攻击伤害 = (dmgMin + rand() × (dmgMax - dmgMin + 1))   // 小队总伤害
              × (士气加成 / 10)                             // 基准 10 → 1.0x
              × 全局系数                                    // 通常 1
              然后按 DOUBLE_DMG_CHANCE 判定是否 ×2
```

- `dmgMin/dmgMax` 是**小队总伤害**：每兵伤害 × 当前存活士兵数，士兵阵亡会实时重算。
- 被冰冻的单位挨打时必吃 `dmgMax`（相当于必中最大伤害）。
- 远程单位被迫近战时，伤害再 ×`(100 − meleePenalty)/100`（弓兵 70 → 只剩 30%）。

| 项目 | 数值/公式 | 说明 |
|---|---|---|
| 攻击伤害 | (dmgMin + rand()×(dmgMax-dmgMin+1)) × (士气加成/10) × 全局系数，取整 | 每名士兵伤害区间 × 存活人数 = 小队伤害 |
| 冰冻时伤害 | dmgMax（取最大值） | 被冻结的单位挨打时吃满伤害 |
| 暴击（双倍伤害） | 概率 = DOUBLE_DMG_CHANCE%，命中则 ×2 | 默认 0，靠修正器/光环提供 |
| 近战惩罚 | 伤害 × (100 − meleePenalty)/100 | 弓兵 70 → 被贴脸只剩 30% 伤害 |
| 士气倍率 | 士气值 / 10（基准 10 = 1.0x） | Heroic +5 → 1.5x；Fear −5 → 0.5x；范围 1-100 |
| 小队人数 | 存活士兵数 0..unitsCount，逐个阵亡实时重算伤害 | HUD 显示 每兵伤害 × 存活数 |
| 冰冻几率/时长 | 几率 = FreezeArrow(或 FreezeBlast)/100；时长 = 3 + 修正 秒 | 每次攻击独立判定 |
| 冲锋 Charge N | 首次接战额外伤害 = floor(伤害 × N / 10) | Charge 2 = +20%；冲锋窗口由 PRP_PURSUIT_TIME 控制 |
| 长枪 LongSpear N | 额外伤害 = floor(伤害 × N / 100) | 50 = +50%（对骑兵额外，PRP_SPEAR_DEFENCE 控制） |
| 盾墙 ShieldWall N | 受到的远程伤害 × N/100 | 15 = 减伤 15%，只作用于 ATK_DISTANCE |
| 毒 Poisonous N | 每 3 秒 −N 点，持续 3 秒 | 可叠加判定，PoisonImmunity 免疫 |
| 溅射 SplashDamage N | 半径 N 像素内的所有目标承受同额伤害 | 投石机 25；不衰减 |
| 攻城 SiegeWeapon N | 对建筑伤害 +N% | 内部存 N×10，50 = +50% |
| 恐吓 Intimidiation N | 命中时降低目标士气加成 | 影响目标后续伤害倍率 |
| 神圣光环 DivinePresence N | 附近友军持续回血 N | 僧人/狂热者 10 |
| 恐怖冲刺 HorrificDash N | 冲刺位移 N | 刺客系突进 |
| 建筑受伤/修复 | 受伤后停止掉血，己方单位进建筑回血；建筑可被占领 | HP 归零后进入占领流程 |
| 建筑升级 | 0→1: 350 金；1→2: 500 金；HP ×(1+0.5×等级) | 最高 2 级 |

## 14. AI 行为（敌方不是脚本波次）

每帧对每个 CPU 玩家依次执行：

1. **补防**：把建筑里闲置的守军拉回节点；
2. **建造/升级**：有空位且钱够就升级建筑（失败则跳过）；
3. **买兵**：`金币 ≥ 180` 且 `空闲补给 > 0` 时，挑**受威胁最大**的己方建筑买 1 队；
4. **移动/攻击**：按状态机决定进攻、撤退、支援；
5. **施法**：终极充能满（`§_-MQ§() ≥ 1`）时按种族放终极技能。

买兵时的选兵规则：先算出该玩家当前可造的兵种列表（受建筑类型 + 科技阶限制），在候选建筑里按 `§_-hI§`（威胁度）加 ±1/3 随机抖动排序，取最高者，再从可选兵种里**随机**挑一个。

目标选择用“血量比例”分档：

| 行为 | 阈值 |
|---|---|
| 集火最弱己方（救援） | 比例 < 0.8 |
| 中等残血（后撤） | 0.3 < 比例 < 0.5 |
| 最强单位（抱团） | 比例 > 0.5，取最大 |

> 关键结论：AI 的买兵门槛是 180 金，而投石机 200 金——所以 **AI 几乎不造攻城器械**，除非修正器降低了造价。
