## 已还原的规则（与反编译结果一致）

- 收入：`round(基础收入 × (100 − (25 + 5×min(队数,10))) / 100)`，最低 1
- 补给：`建筑 Supply 之和` vs `小队 Upkeep 之和`；不足不能造兵
- 造价：步兵 100 / 弓兵 120 / 骑兵 180 / 特殊 150 / 攻城 200；攻城占 2 补给
- 升级：0→1 级 350 金，1→2 级 500 金；`HP = 基础 HP × (1 + 0.5 × 等级)`
- 建筑等级决定科技阶：0 级→1 阶，1 级→2 阶，2 级→3 阶
- 伤害：`Rand(dmgMin, dmgMax) × 存活人数`，远程被贴脸再 ×`(100 − meleePenalty)/100`
- 攻城：带 `SiegeWeapon` 的小队对建筑 ×1.5
- 占领：建筑 HP 归零后归属转移，等级清零、恢复 30% HP
- AI：金币 ≥ 180 且有空闲补给才买兵；空闲小队自动打最近的玩家建筑

## 第三轮：修掉僵局，测试台升级为“真配置”

### 1. 僵局根因

L4 打到 900 秒不动，原因很具体：

- AI 会在**孤立空地**上建农场（空地不在道路图里）
- 这些小建筑永远走不到，却被算进“敌方建筑”
- 玩家 8 队兵卡在路口，胜负判定永远不满足

修复：胜负与索敌都只看**主建筑**（要塞/城镇/营地/魔法塔，building id 1-4）；农场/矿场/英雄碑不再影响胜负。

### 2. 24 关扫描（脚本玩家）

| 指标 | 结果 |
|---|---|
| 胜 | 14/24 |
| 平局 | 0 |
| 前 8 关 | 4 胜 4 负（L2、L3 仍偏难） |

脚本玩家只会“铺农场 + 买最便宜的兵 + 打最近的主建筑”，所以这个数字是**下限**，不是关卡真实难度。

### 3. 测试台不再用 JSON 假数据

原来无头测试用导出的 `data.json`，现在改成**直接读 Luban 生成的 `takeover_*.bytes`**，并编译真实的生成类（`GameConfig.takeover.*` + `Luban.ByteBuf`）。

这意味着以下链路已被验证：

- Excel → Luban → `.bytes` → 反序列化 → 模拟
- 字段名/类型（`Loc`、`BuildCost`、`AllowedTypes`）与业务代码一致

唯一还没验证的只剩 Unity 的渲染与交互层。

## 第七轮：核心操控与远程战斗

### 1. 操控

| 操作 | 行为 |
|---|---|
| 左键点小队 | 选中（白框高亮，右侧显示人数/HP/射程/目标） |
| 左键点建筑/空地 | 选中，出建造/造兵面板 |
| 右键点节点 | 有选中小队 → 单队前往；无 → 全军进攻 |
| H | 选中小队撤退回最近己方建筑 |
| 滚轮 | 缩放（60-700） |
| WASD / 方向键 / 中键拖拽 | 平移 |

### 2. 远程战斗

战斗从“同节点结算”改成**按距离判定**：近战有效距离 40，远程用自身射程（弓 100、投石机 200）。远程因此能在近战贴上来之前先开火；被贴到 40 内仍然吃 `meleePenalty`。

单元测试（`dotnet run -- range`）：

`
弓兵射程=100 攻击间隔=3s
敌人 HP 162 → 102     ← 80px 外挨了一箭
近战距离敌人 408px，射程 0，应无伤害   ← 近战够不到
`

### 3. 驻军出战

驻军 140px 内有敌人就出城迎战，敌人走远自动回防（`HomeNode`）。之前守军是站着等死。

### 4. 修掉一个数值 bug：士气倍率

之前把兵种表的 `morale=50` 当成了伤害倍率，实际原版 `PRP_MORALE_BONUS` 基准是 **10（=1.0x）**，`morale` 只是士气池。这个错误让**所有伤害被放大 5 倍**，也是之前关卡 30-40 秒就能推完的原因。

修复后：L1 从 36 秒变成 **87 秒**，全关胜率 18/24 → **15/24**，节奏明显更像原版。

### 5. 其他

- 关掉了 TEngine 自带的 DEBUGGER 悬浮面板（会挡住玩法 HUD）：`GameModule.Debugger.ActiveWindow = false`
- 补员：在己方建筑内回血会把阵亡士兵按血量阈值补回来（`AliveSoldiers` 由 HP 推导），已随回血逻辑生效

## 第八轮：AI 撤退与增援

### 行为

| 行为 | 规则 |
|---|---|
| 撤退 | 小队血量 < **32%** → 标记撤退，回最近己方建筑；血量 > **75%** 才重新出动 |
| 增援 | 己方建筑 220px 内出现敌军且附近守军 < 2 队 → 派最近的空闲小队回防 |
| 防守优先 | 老家被逼近时**整波不出击**（先守） |
| 买兵 | 优先补到被围攻的那座建筑，而不是随机挑 |
| 进攻 | 只派“健康 + 未撤退 + 空闲”的小队，且始终留 1 队守家 |

### 顺手修掉一个寻路 bug

`OrderMove` 从“最近节点”出发时，如果最近节点是**孤立建造点**（没有边），`FindPath` 返回 null，小队就永远不动。

现在会退回到最近的**连通节点**重新寻路。

### 验证

`dotnet run -- ai`：

`
[ai] 残血小队 HP=40/162  Retreating=True
[ai] 是否在往己方建筑移动：是，剩余 1 段
`

24 关扫描：**15/24 → 12/24**（AI 明显变强，符合预期）；L1 仍可通，用时 98 秒。
